30006 → 30555，step6000 推理自检

适用范围
服务器现有 StableAnimator、animate 环境及原模型文件。主实验使用 command_ipi_infer.sh、
inference_latent_ar.py、inference_pipeline_animation_ipi.py、unet_ipi.py。此链没有 OP。
下文所有 121–140 均为从 0 开始计数的源帧，短片 frame_0.png 对应源帧 121。

十轮检查记录

1. 启动参数。旧主入口给 min/max CFG 预设了 2 和 3.5，GUIDANCE_SCALE 被覆盖。
   现由 Python 解析明确端点。shell 空配置保留原来的 2→3.5；显式 GUIDANCE_SCALE=3
   表示固定为 3。实验脚本显式写出旧端点。旧版 basic、long、OP 等启动器加入退出码检查，
   以项目目录为基准解析路径，阻止失败后拿旧帧编码。
2. 输入与坐标。normalized 的单边 -1 表示关节缺失；model 坐标的 (-1, 0.5)
   是有效边界，现保留。核对原始长度、数值帧号、截取端点及像素映射。主入口的
   RETARGET=1 用 .npy 重新画控制图，配置中打印的 PNG 控制目录此时没有参与绘制。
   旧 IPI 入口共用读取与校验，防止独立截短 RGB、控制图和 NPY 后仍继续。
3. 身体对齐。保存的短片前 18 个点逐值等于整段对应切片。用实际训练和推理的绘图函数
   对同一个重定位后身体骨架逐帧重画，20 张图逐像素相同。新增 POSE_ROOT_MOTION_SCALE；
   1 保留原始根位移，0 固定首个有效颈部或髋部锚点。两者均用整段求对齐后再截取，
   使用同一套肢段比例与颜色，改变条件骨架位置时要检查出界点和参考主体位置。
4. 权重。主入口要求完整的 PoseNet、UNet 和 FaceEncoder。PoseNet 的最后投影初始化为零，
   允许空权重会直接丧失空间控制。严格检查骨干缺键和多余键；v2 开启时在模块兼容
   加载旧权重的逻辑之前核对门控和投影。单独导出的 IPI Adapter 最后加载。
5. PoseNet/UNet/IPI。条件支路用本窗 PoseNet 输出，非条件支路用零 pose。UNet 在
   conv_in 后加 pose_latents × pose_scale；PoseNet 自己还有已学习的 scale。训练该路径
   默认取 3，与本例推理相同。新增张量形状和不完整 IPI 输入检查，防止静默广播或旁路。
   IPI v2 将每帧 token 平均、投影、乘 tanh(gate)，向空间位置广播。
6. 时间窗口。主入口在每个去噪步覆盖所有帧后做加权平均，再调用一次 scheduler.step。
   末窗没有粘贴参考图。短片重启了 CFG 时间轴和周期噪声相位；SOURCE_TIMELINE=1
   可在短片内取完整序列对应的 CFG 和初始噪声。它不会模拟其他窗口对该帧的预测。
   独立噪声模式结合该选项需采样全长初始噪声；本组对照保留周期噪声。
   旧 basic/OP/long 实现另修零重叠覆盖、短窗权重、条件切片与过短尾窗。
7. 参考姿态条件。空间参考 VAE latent 拼进每帧、每个去噪步。新增 REFERENCE_LATENT_SCALE
   衰减该通道。REFERENCE_CLIP_SCALE 另外控制全局图像 token，作用在身份融合之后。
   默认两项均为 1。它们能改变外观或材质；实验同时看关节和身份保持。
8. 身份条件。修正主入口参考图送入人脸检测的 RGB/BGR 转换。记录检测成功、
   对齐脸、零向量参与融合、关闭四种实际来源。身份 token 全零时，旧归一化仍会
   加回全局特征均值。现以 FP32 计算统计，禁用身份时残差为零。同时修复普通
   ID attention 的 PyTorch 回退路径误用全局 K/V。主 6000 路径使用归一化处理器。
   此修复可能改变同种子的基准图，共享处理器也会影响以后使用它的训练。
9. 扩散时间与条件。20/40 步均传给 scheduler；进度条次数还乘以窗口数量。
   单窗复用与 timestep 无关的 PoseNet 特征。新增 FPS_TIME_ID 与实际 scheduler
   步数、CFG 首尾、PoseNet 已学习倍率、各 v2 门控的日志。训练 time ID 为
   14、动态 motion bucket 约 80–160、默认参考噪声 0.04。历史短片为 6、300、0。
   这三项在首轮实验固定，导出视频每秒 24 帧与模型 FPS 条件互相独立。
10. 交叉验证。对真实 NPY 检查帧段与角度。用代替模型的数值桩执行主 pipeline 实际
    去噪循环，在单窗/多窗、开关 IPI、CFG=1/开启、20/40 步下核对条件、帧号、
    参考通道、窗口归一化及 scheduler 调用数。旧管线另测边界配置。
    实验 runner 显式固定种子和有效 CFG；对共享目标的组比较 NPY 字节。
    脚本通过语法/编译检查，真实 step6000 的 GPU 成片仍需在服务器生成。

按本例相关性排序

高：控制骨架在画布上的位置与雕像实际肢体有偏差，或者模型对正确位置的控制不足。
这会直接表现为手腕轨迹和膝角跟丢。源帧 121→140 的右膝目标从 177.5° 降至
130.7°，左膝从 175.8° 降至 144.9°。根节点在整段首帧至末帧向右下移动约
73、59 像素，而重定位后的中位肩宽约 55 像素。位移是否合适要用 root0 验证。
高：训练 dataset 只对驱动骨架做部分几何变换，目标 RGB 没有同步做对应变换。
以同一 30006 的第 0 帧为参考、121–140 为目标，关闭随机增强，代入实际训练几何函数，
与原目标点比较，右腕、左腕、右膝、左膝的中位偏移是 61.7、102.8、88.4、86.3 px。
这是可重现的训练样例构造，不代表已恢复训练抽样历史。跨主体局部驱动变弱有这一可能机制。
从 31000 开始的 IPI-only 训练冻结 PoseNet 和基础 UNet；更新推理代码不会修正已有监督。
高：重复参考空间 latent 和全局参考 token 始终提供原图信息；可能让局部肢体倾向原姿势。
两者并无读取“应当何时回原图”的规则。通过分别改变参考尺度验证因果。
中：IPI v2 的逐帧残差没有单独的腕/膝空间图。它可以间接影响局部生成。
6000 的这组 on/off 暂未显示稳定的关节改善；门控非零也不等于改善。
中：CFG 参数遮蔽是已证实 bug；短片相位、训练/推理 time IDs、噪声和步数是实验混杂因素。
中：模型坐标边界丢点、静默加载不全权重、广播错形状、索引截短可直接破坏控制；
目前这组历史产物没有证据触发这些缺陷。30006 原始 RGB 与姿态 PNG 为 768×1152，
30555 参考图为 534×800；目标为 512×768，三者纵横比接近。
低（本例）：旧版 OP 的 A/B/C 原跨不同预处理与管线。统一入口后 A 关闭优化，B/C
按步数开启。原目标是整图 CLIP；显式 OP_REGION=face 需给出参考脸与输出主体逐帧对应
的目标脸掩码，才会比较脸部区域。旧版 basic/long/OP 窗口和 mask 错误也与主样例分开。
其他入口：Gradio 曾在提取失败后把参考图当作每帧控制图，并用全零 NPY 继续，
生成异常时还可能返回已有视频。此类假控制可直接使主体停在参考姿态，但服务器
Bash 实验没有走这里。现校验真实控制、权重和生成帧数，失败就报错。界面改读
环境变量提供此前硬编码的外部服务凭据。小包只更新主实验，大包也包含这些旧入口。

服务器实验

进入 /gaojiawei/wjl/StableAnimator 并激活原 animate 环境。
先执行 bash tools/run_30006_joint_ablation.sh base pose0 root0 ref075
然后执行 bash tools/run_30006_joint_ablation.sh pose45 steps40 ipi_on
每组生成 20 帧，目录为 basic_infer/30006_joint_ablation_6000/<组名>。
已存在的同名组会报错，可指定新 EXPERIMENT_ROOT。已安装完整模型环境时运行
python tools/evaluate_joint_following.py ./basic_infer/30006_joint_ablation_6000/base
同一检测器、画布、有效帧比较腕/膝像素误差、肩腕方向、膝角；报告可检出帧数，
只有双方均检出的同一帧才适合成对比较。无可靠检测时人工核对 121、138、140 帧。
base 与 pose0 测整体 pose 灵敏度；pose45 测放大是否仍只形成重影。root0 测根位移；
ref075 只将空间参考幅度乘 0.75；steps40 只加采样步数；ipi_on 只开启 v2。
root0 应对它自己的目标骨架评分，并额外检查与驱动动作的语义和参考形体的一致性。
单个雕像/种子的结果只支持该用例；报告普适增益需要多组迁移和种子。
